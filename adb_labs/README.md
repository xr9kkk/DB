Начни с инструкции выбранной работы: там описаны вход в SQL Shell, команды и объяснения, порядок переключения окон, ожидаемые результаты и вопросы на защите. Учебные объекты уже созданы, но перед демонстрацией запускай подготовку нужной работы, чтобы получить исходное состояние. Подготовку нельзя выполнять, пока другие учебные окна держат открытые транзакции.

Проверки: [verification_result.txt](verification_result.txt). Полученные планы: [lab4/plans_result.txt](lab4/plans_result.txt). Первая работа: 17 проверок пройдены; делегирование и CASCADE также проверены.

`verify_labs.py` — дополнительная автоматическая проверка через независимые соединения, не нужна для сдачи. Требует `psycopg[binary]`; перед запуском подготовь lab2 и lab3, создай объекты lab4. Она меняет только учебные данные, временно проверяет процедуру employee с ROLLBACK, завершает только собственное соединение и после проверки возвращает учебные значения и autovacuum. Пароли в файлах — учебные из текущего задания.

Правка PUBLIC в первой работе выполнена в исходных скриптах: общие отзывы удалены. Ранее отозванные права в живой базе не восстанавливались без исходного списка прав. В четвёртой работе есть точечный отзыв EXECUTE только на две новые учебные функции для демонстрации безопасности; прочие права PUBLIC не затрагиваются.

Правила сценариев сверены с официальной документацией: [изоляция](https://www.postgresql.org/docs/18/transaction-iso.html), [блокировки](https://www.postgresql.org/docs/18/explicit-locking.html), [функции](https://www.postgresql.org/docs/18/sql-createfunction.html).
